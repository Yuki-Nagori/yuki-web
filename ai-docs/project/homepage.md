# 首页与风格展示架构

## 产品方向

首页是一个持续增加风格的展示网站。每种风格在首页占据一个屏幕，拥有独立的视觉设计和配套组件库；各风格的源码、组件、样式和素材相对独立存放，便于单独迭代。

首页负责串联各个展示屏；具体风格负责自己的画面与交互。首个风格为
[中国古风：朱墙冬梅](../plans/001-chinese-winter-plum.md)。

## 首页体验

- 各展示屏纵向排列，用户通过自然滚动浏览。
- 每屏以一个视口为基本尺度，使用
  `min-height: 100dvh`；小屏或内容较多时允许自然增高。
- 每屏是一幅完整的风格展示，包含主视觉、风格名称、简短文案和适量交互。
- 如使用滚动吸附，采用温和的 `proximity`，保留键盘、触控和正常页面滚动。
- 展示屏可提供进入该风格完整示例与组件展示的入口；独立页面和路由在实际开发时添加。
- 原有版权与备案 footer 放在所有展示屏之后，由首页统一管理。

## 模块组织

建议按风格组织，而不是将所有风格的组件混放在全局 `components/`：

```text
src/
├── views/
│   └── home/
│       └── HomeView.vue             # 组装风格展示屏和网站 footer
├── showcases/
│   ├── registry.ts                 # 展示顺序、名称与模块入口
│   ├── types.ts                    # 风格模块共享的最小接口
│   └── chinese-winter-plum/
│       ├── index.ts                # 模块公开入口
│       ├── Showcase.vue            # 首页整屏展示
│       ├── components/             # 场景组件，如朱墙、梅枝、题字
│       ├── ui/                     # 该风格的组件库，如按钮、卡片、分隔线
│       ├── composables/            # 该风格专用的交互与响应式逻辑
│       ├── assets/                 # 该风格的图片、字体和纹理
│       └── styles/
│           └── theme.css           # 该风格的色彩、字体和局部样式
├── components/                     # 网站公共组件，如 SiteFooter
├── App.vue
└── main.ts
```

以上是计划结构，按实现进度创建文件，不提前建立空模块。

## 独立性与组件库

- 每个风格模块提供一个可嵌入首页的展示组件；首页通过公开入口使用模块。
- 风格模块内部使用相对路径，不引用其他风格模块的内部组件、素材或样式。
- `ui/`
  存放该风格自己的可复用组件，统一颜色、字体、间距、边框、交互状态和组件接口。
- 场景组件与 UI 组件分开：梅枝、宫墙属于场景；按钮、卡片属于配套组件库。
- 先实现画面真正需要的组件，逐步补齐组件展示；第三方组件库按需求选择。
- 只有跨风格共用且不带视觉偏好的功能，才提取到网站公共目录。
- 色彩和字体变量限定在风格根容器，组件样式使用 scoped CSS 或模块前缀。
- 不在全局修改
  `body`、`button`、标题等元素的风格，也不将单一风格的主题注册成全站默认主题。
- 进入独立示例页时可复用同一模块，不复制整份实现。

## 加载与适配

展示顺序和模块信息集中登记；后续新增风格以添加模块和登记信息为主要改动。首屏优先加载，后续屏幕的重素材与可选功能按需加载，避免首页一次下载所有风格资源。

每个模块都需要验证桌面和手机画面、文字可读性、键盘焦点及减少动态效果偏好。装饰层不阻挡交互，动画不影响阅读；不要依赖鼠标悬停才能访问主要内容。
